## Methodology

- **Test set**: the archive's own test file (2 000 pairs), never read by `prepare`,
  `train`, or the slice-threshold computation. Smoke runs cap it via
  `data.max_test_samples`.
- **Relative L2**: `||pred − ref||₂ / max(||ref||₂, ε)` per sample over the 32×32 grid,
  in field units; `ε` is `evaluation.relative_l2_epsilon`, and the number of samples
  that hit the floor is reported.
- **MAE**: mean absolute error per sample in the field's stored units (unknown physical
  units; see `docs/data.md`).
- **Enstrophy error**: enstrophy is `0.5 · mean(ω²)` over the grid (the domain size is
  unknown, so a grid mean replaces the area integral). The relative error is
  `|E(pred) − E(ref)| / max(E(ref), ε)`; the absolute error is also stored in
  `metrics.json`.
- **Worst case** is the maximum over test samples; the median is stored as well.
- **High-vorticity slice**: samples whose reference field has `max|ω|` at or above the
  `evaluation.high_vorticity_quantile` quantile of the same statistic over the
  train+validation reference fields. The threshold is derived without touching the
  test set.
- **Latency**: batch-one, the full preprocess → model → postprocess path used by the
  API (`flowbench.serving.predictor.FieldPredictor.predict`), device-synchronised,
  after `latency.warmup_iterations` untimed calls; p50/p95 over
  `latency.timed_iterations` calls. HTTP overhead is excluded. Numbers depend on the
  machine and are reported with the device.
- **Persistence** is evaluated through the identical path with no parameters, so the
  comparison is like for like. No numerical solver is timed; nothing here supports a
  speed-up claim.
